AgriFlow AI: System Design Specification

Project Documentation & Architectural Design Report
Domain: AI-Powered Organic Produce Management & Recurring Delivery Platform

1. Problem Statement

1.1 Background & Context

The agricultural and organic food supply chain plays an indispensable role in daily consumer health and sustainable farming ecosystems. However, local organic farming commerce in developing and urban fringe markets remains heavily burdened by legacy, fragmented, and manual operational models. Smallholder organic farmers, local distributors, and end-consumers encounter severe friction at each phase of the supply cycle—from harvest forecasting and catalog management to daily subscription logistics, advance billing, and delivery validation.

1.2 Core Issues in Existing Systems

  • Disjointed Communication Networks: Farmers and vendors lack a unified digital platform to coordinate with consumers. Routine operations depend on scattered telephone calls, unorganized messaging threads, and paper ledgers, causing frequent order errors.
  • Manual Subscription Inefficiencies: Daily household essentials like fresh organic milk or weekly vegetable hampers require recurring fulfillment. Traditional e-commerce platforms cater only to one-time orders; manual tracking of customer pauses, vacations, and frequency shifts results in untraceable payments and missed deliveries.
  • Lack of Delivery Traceability: Deliveries frequently occur in early morning hours without physical customer handoffs. Without geo-tagged drop logs and multi-channel validation (such as automated voice calls), misdeliveries or missing items remain untraceable.
  • Heavy Administrative Overhead: Business owners spend significant daily effort verifying manual UPI payments, reconciling bank ledgers, tallying daily harvest needs, and fielding repetitive queries.

1.3 Proposed AgriFlow AI Solution

AgriFlow AI introduces an integrated, micro-packaged platform featuring a decoupled 3-tier architecture, an autonomous cron-based subscription and wallet auto-debit engine, natural language conversational interfaces (OpenAI / Ollama) across mobile and WhatsApp, and automated Twilio voice delivery validations.

2. Project Objectives

2.1 Primary Objectives

  1. Deliver a Multi-Role Digital Hub: Provide specialized interfaces for Customers (catalog browsing, wallet recharge, subscription builder), Farmers/Vendors (inventory stock and harvest manifest), and Administrators (financial analytics and platform health).
  2. Automate the Subscription Lifecycle: Provide flexible frequencies (Daily, Alternate Days, Weekly) supported by scheduled midnight wallet deductions and automatic harvest manifest compilation.
  3. Deploy AI-Powered Customer Assistance: Equip users with an AI assistant capable of answering product inquiries, checking seasonal crop availability, and updating subscriptions via WhatsApp and mobile chat.
  4. Ensure Delivery Integrity: Implement driver drop verification backed by automated outbound Twilio voice confirmation calls with fail-safe push notification fallbacks.

2.2 Specific Technical Goals

  • High-Performance REST API: Sub-200ms query resolution using Node.js, Express, TypeScript, and PostgreSQL with Prisma ORM.
  • Autonomous Background Processing: Dedicated node-cron daemons executing midnight auto-debits and generating daily harvest manifests before early morning delivery shifts.

3.1 Layer Details

  • Presentation Tier: Encapsulates client apps. The mobile application caters to consumers and field drivers, while the administrative web portal provides business metrics.
  • Application / Business Logic Tier: Houses business rules, state machines for orders and subscriptions, cryptographic security (Bcrypt, JWT), and autonomous scheduled cron jobs.
  • Data Persistence Tier: PostgreSQL relational database ensuring ACID transactional integrity, managed via Prisma ORM schemas.
  • External Integrations: External bridges including Razorpay, Twilio Voice, WhatsApp Cloud API, and Firebase.

4. Use Case Specifications & Diagram

4.1 Identified System Actors

  • Customer: Browses produce, manages digital wallet, creates recurring subscriptions, chats with AI assistant.
  • Farmer / Vendor: Updates inventory stock, views daily aggregated harvest quotas.
  • Delivery Driver: Navigates delivery routes, marks order drop completion, triggers voice validation calls.
  • Administrator: Oversees platform metrics, approves products, inspects system logs and audit trails.
  • AI Engine & Cron Schedulers: Automated system actors handling background deductions and conversational parsing.

4.2 Key Use Case Details

Attribute Use Case UC-01: Create Recurring Subscription
Primary Actor Customer
Preconditions Customer is logged in; wallet balance is loaded.
Main Flow 1. Customer selects organic item (e.g., Farm Milk) and taps "Subscribe".
2. Selects frequency (Daily/Weekly) and start date.
3. System validates wallet balance.
4. Customer confirms and subscription status is set to ACTIVE.
5. Next delivery date is recorded in database.
Alternative Flow If wallet balance is low, system prompts instant Razorpay recharge before activating subscription.
Attribute Use Case UC-02: Delivery Confirmation & Voice Validation
Primary Actor Delivery Driver & Twilio Cloud Service
Preconditions Order is OUT_FOR_DELIVERY; driver arrives at customer location.
Main Flow 1. Driver deposits items at customer doorstep.
2. Driver taps "Confirm Drop-off" on AgriApp mobile screen.
3. Status updates to DELIVERED.
4. Twilio Voice API places automated confirmation call to customer.
5. Call result logged in system audit trail.
Alternative Flow If customer does not answer phone, automated fallback triggers WhatsApp delivery alert and Firebase push notification.

6. UML Diagrams

6.1 Class Diagram Specifications

Key entities and relationships modeled in the system:

  • User (Base Class): id, name, email, phone, role, passwordHash | Methods: login(), register(), updateProfile()
  • Customer (Inherits User): deliveryAddress, coordinates | Methods: rechargeWallet(), createSubscription()
  • Farmer (Inherits User): farmName, certificationNo | Methods: updateStock(), getHarvestManifest()
  • Driver (Inherits User): vehicleNo, licenseId | Methods: markDelivered(), getActiveDeliveries()
  • Wallet: id, userId, balance, updatedAt | Methods: credit(), debit(), getBalance()
  • Subscription: id, customerId, productId, frequency, status, nextDeliveryDate | Methods: pause(), resume(), cancel()
  • Product: id, categoryId, title, price, unitType, stockQuantity, isOrganic | Methods: reduceStock(), checkAvailability()
  • Delivery: id, orderId, driverId, status, voiceConfirmed, dropTime | Methods: triggerVoiceConfirmation()

6.2 Sequence Diagram: Midnight Subscription Processing

1. Cron Daemon triggers Subscription Service at 00:00 AM daily. 2. Subscription Service queries PostgreSQL for active subscriptions where nextDeliveryDate == Today. 3. For each active subscription: a. Check Customer Wallet balance. b. IF Balance >= Daily Price: - Wallet Service debits wallet and records Transaction. - System creates Order record with status 'PLACED'. - Advances nextDeliveryDate to the next cycle. - Triggers Firebase notification: "Morning delivery scheduled". c. ELSE (Insufficient Balance): - Marks subscription status as 'PAYMENT_PENDING'. - Dispatches WhatsApp reminder: "Please recharge wallet to resume deliveries". 4. System compiles total quantities into the Daily Harvest Manifest.
